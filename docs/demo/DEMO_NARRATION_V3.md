# Demo narration v3

A checkout incident hits while fifty agents share durable memory. One trusted
observation is stored. A poisoned instruction that says to disable payment
verification is rejected. Amazon Titan retrieves the verified recovery, and
two workers race to act. CockroachDB records exactly one owner. This is a live,
fixed-input replay against the participant AWS and CockroachDB deployment.

Continuum Memory Firewall separates relevance from authority. A short-lived
Cognito token verifies the caller. An audited tenant binding chooses a
server-owned scope. That scope selects a deterministic, no-bypass SQL role.
CockroachDB row-level security independently enforces the same tenant and
incident at every row. Caller input cannot widen it.

Quality is measured with an attacker in the room. Titan version two evaluated
sixty paraphrase, terse, typo, negation, misleading-scope, and multi-intent
queries. Recall at three was ninety-eight point three percent. Recall at five
was one hundred percent. A foreign memory with a perfect semantic match still
returned zero rows.

The vector index is also proven at real scale, not on a toy table. Exact scans
establish ground truth over ten thousand and fifty thousand non-sensitive,
five-hundred-and-twelve-dimensional vectors. CockroachDB naturally chooses the
vector search operator. At fifty thousand rows, beam five hundred twelve
reaches ninety-six point nine percent Recall at ten with a warm p-ninety-five
of three hundred fourteen milliseconds.

Then ten, twenty-five, and fifty concurrent agents run a measured mix of vector
reads, trusted promotions, and action claims. Eight hundred fifty operations
finish with zero worker errors, zero foreign rows, and one durable owner at
every level. Throughput peaks at eighty point four operations per second with
twenty-five agents. At fifty, the bounded twenty-connection pool queues work;
correctness holds and recovery after deliberate pool teardown takes one hundred
eighteen milliseconds. The evidence tells us the next optimization is
admission control, not an unsafe unbounded pool.

Finally, the judge presses one public, read-only button. It verifies exact
workflow heads, artifact hashes, live MCP health, deployment lineage, database
isolation, scale, pressure, key rotation, and the submitted Devpost receipt.
No credential or write permission is exposed.

Similarity may propose a memory. The database decides authority. Long-running
agents need memory. Production agents need a memory firewall.
